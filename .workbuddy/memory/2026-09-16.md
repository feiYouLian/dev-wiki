## 修复 `npm run docs:build` 的 Vue 标签未闭合报错
- CI（GitHub Actions `feiYouLian/dev-wiki`）报 `docs/spring/spring-mvc.md (215:43): Element is missing end tag.`。
- 根因：VitePress 用 Vue 编译 Markdown，正文/表格单元格里裸写的 `<...>`（`<` 后紧跟字母）会被当成未闭合 HTML 标签。spring-mvc.md:175 表格单元格里的 `ResponseEntity<StreamingResponseBody>` 是首个触发点（报错行号是 Vue 栈回溯位置，并非真正出问题的行）。
- 排查方法：用 node 脚本扫描 `docs/**/*.md`，找「不在代码围栏、不在行内反引号、非 `\<` 转义、非 `<http` 自动链接」的裸 `<[A-Za-z]`。注意：我的简单围栏计数器在 `spring内置功能.md` 因围栏翻转误报 pom 块（实际在 ```xml 围栏内，安全，且此前构建已通过，无需改）。
- 实际需修的 3 处（全部用行内反引号包住泛型，使其被 markdown 转义为字面文本）：
  - `docs/spring/spring-mvc.md:175`：`ResponseEntity<StreamingResponseBody>` → 包反引号
  - `docs/spring/spring-tips.md:202,203`：`**Converter<S,T>**` / `**ConverterFactory<S, R>**` → 内联代码
  - `docs/java/HashMap/HashMap.md:265`：标题 `treeifyBin(Node<K,V>[] tab, int hash)` → 包反引号
- docker/index.md 的 `<image>/<command>/<src>/<dest>/<key>/<value>` 经核对早已在反引号内，无需改。
- 验证：修复后 `vitepress build docs` 成功（exit 0，build complete in 94.94s，零死链零报错）。
- 经验：此类「迁移过来的技术笔记」通病——Java 泛型 `List<X>`、占位符 `<src>` 写在正文而非代码块时会炸构建。通用修法是包反引号或整段加 `v-pre`。
