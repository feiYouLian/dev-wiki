### 方法论（本次沉淀，可复用）
- **大批量改同一文件：按行号区间「自底向上」替换**。先算好每段的 1-based 起止行（`lines[start-1:end] = new`），按 `start` 降序应用，前面段落的行号就不受影响。比逐个 Edit 稳得多，也彻底避开「同文件并行 Edit 互相覆盖」的老坑；脚本还能顺带跑校验（围栏配对 / 裸尖括号 / `{{` / 标题清单）。
- **小范围替换**用「目标块 → 新块」，并对每行做 `rstrip()` 归一化比较来定位；但多行精确匹配很脆（尾随空格、双宽字符内部间距），**能用行号就别用长块文本匹配**。
- ⚠️ 踩坑：自写 `find_block()` 时犯了 `for x in target`（`target` 是 str，迭代的是**字符**不是行）→ 必须先 `target.split('\n')`。结果表现为「全部 hits=0」。
- ⚠️ 校验脚本的 `expected` 计数很有用：同一段文字在文档里出现 2 次（速查节 + 正文节）时，要显式给 `expected=2`，否则会因计数不符而整体跳过（本次两处 Spring 图就因此漏了一处，需二次补修）。
