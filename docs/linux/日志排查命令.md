# Linux 日志排查命令组合拳（tail / less / grep / sed / awk）

> 本文总结自掘金文章《同事查日志太慢，我现场教他一套 awk、tail、grep、sed 组合拳》（作者：程序员小富，2025-12-26）。
> 原文链接：<https://juejin.cn/post/7587714124856770614>
>
> 面向后端开发，整理基于 `tail`、`less`、`grep`、`sed`、`awk` 的常用日志排查场景，下次遇到生产问题对着场景复制粘贴即可。

## 背景

后端开发熟练掌握 Linux 日志分析命令是基本功。新手常习惯用 `cat` 打开大日志文件（比如一个 2GB 的文本），结果屏幕疯狂刷屏、终端卡死，`Ctrl + C` 都来不及停。

对于大文件，`cat` 会一次性输出全部内容，而下面这几条命令才是正解。

## tail —— 实时监控文件尾部

`tail` 是实时监控神器，不会把历史内容一股脑刷出来。

- **场景 A：服务发版启动监控**——确认 Spring Boot 是否启动成功、有无初始化报错：

  ```bash
  # -f (follow)：实时追加显示文件尾部内容
  tail -f logs/application.log
  ```

- **场景 B：配合测试复现 Bug**——测试说“我点一下按钮你看后台有没有报错”，只需盯着最新输出，别被历史日志干扰：

  ```bash
  # 只看最后 200 行，并保持实时刷新
  tail -n 200 -f logs/application.log
  ```

## less —— 按需加载、回溯历史

需要查看之前的日志时推荐 `less`。不同于 `vim` 会一次性加载整个文件占满内存，`less` 按需加载，打开几个 G 的文件也极其流畅，且支持向后回溯。

- **真实场景：追查某笔客诉订单**——运营反馈“刚才 10 点左右，订单号 `ORD12345678` 支付失败了”，需要从日志末尾往前反向查找：

  ```bash
  less logs/application.log
  ```

  进入界面后的操作流：

  1. `Shift + G`：先跳到日志最末尾（报错通常发生在最近）。
  2. `?ORD12345678`：输入 `?` + 订单号，**向上反向搜索**。
  3. `n`：当前这行不是关键信息，按 `n` 继续向上找上一次出现的位置。
  4. `Shift + F`：看着看着日志又更新了，按此组合键进入类似 `tail -f` 的实时滚动模式；按 `Ctrl + C` 退回浏览模式。

## grep —— 关键字搜索

`grep` 最常用，但实际业务中简单的关键词搜索往往不够，需要配合参数。

- **场景 A：还原报错现场（关键）**——只看到 `NullPointerException` 一行往往无法定位问题，必须配合 `-C`（Context）看报错前后的请求参数与堆栈：

  ```bash
  # 搜索异常关键字，并显示该行前后各 20 行
  grep -C 20 "NullPointerException" logs/application.log
  ```

- **场景 B：全链路追踪 TraceId**——微服务通过 `TraceId` 串联请求，日志滚动后变成 `app.log`、`app.log.1`、`app.log.2`，需要在所有滚动文件中搜索同一个 TraceId：

  ```bash
  # 搜索当前目录下所有以 app.log 开头的文件
  grep "TraceId-20251219001" logs/app.log*
  ```

- **场景 C：统计异常频次**——老板问“Redis 超时今天发生了多少次？偶发还是大规模？”直接统计行数：

  ```bash
  # -c (count)：只统计匹配的行数
  grep -c "RedisConnectionException" logs/application.log
  ```

- **场景 D：排除干扰噪音**——排查时被大量无关的 `INFO` 心跳/健康检查日志干扰视线：

  ```bash
  # -v (invert)：显示不包含 "HealthCheck" 的所有行
  grep -v "HealthCheck" logs/application.log
  ```

## sed —— 按时间窗口切分日志

日志非常大（如 10GB），`grep` 搜出来的内容依然过多。如果明确知道事故发生在 **14:00–14:05** 之间，用 `sed` 把这段时间单独切出来保存成小文件慢慢分析。

```bash
# 语法：sed -n '/开始时间/,/结束时间/p' 源文件 > 目标文件
# 注意：时间格式必须和日志里的格式完全一致
sed -n '/2025-12-19 14:00/,/2025-12-19 14:05/p' logs/application.log > error_segment.log
```

这样就得到了一个只有几 MB 的 `error_segment.log`，下载到本地分析或发给同事都非常方便。

## awk —— 列数据分析 / 生成简报

`awk` 擅长处理列数据，对格式规范的日志（Nginx、Apache 访问日志）可直接在服务器上生成简报。

- **场景 A：遭到攻击，查找恶意 IP**——服务报警 CPU 飙升，怀疑 CC 攻击或爬虫，分析 Nginx 日志找出访问量最高的 IP（假设第一列是 IP）：

  ```bash
  # 1. awk '{print $1}'       提取第一列（IP）
  # 2. sort                   排序，相同 IP 排在一起
  # 3. uniq -c                去重并统计每个 IP 出现次数
  # 4. sort -nr               按次数(n)倒序(r)排列
  # 5. head -n 10             取前 10 名
  awk '{print $1}' access.log | sort | uniq -c | sort -nr | head -n 10
  ```

- **场景 B：找出响应最慢的接口**——Nginx 日志记录了响应时间，假设在最后一列，把响应时间超过 1 秒的请求找出来：

  ```bash
  # $NF 代表最后一列
  # 打印所有响应时间大于 1 秒的 URL（假设 URL 在第 7 列）
  awk '$NF > 1.000 {print $7, $NF}' access.log
  ```

## 小结

| 命令 | 用途 | 关键参数 / 组合 |
| --- | --- | --- |
| `tail` | 实时监控与复现 | `-f`、`-n 200 -f` |
| `less` | 回溯历史、定位订单 | `Shift+G` 跳末尾、`?` 反向搜、`Shift+F` 实时滚动 |
| `grep` | 上下文 / 统计 / 过滤 / TraceId | `-C 20`、`-c`、`-v`、跨文件 `app.log*` |
| `sed` | 大日志按时间段瘦身 | `-n '/起/,/止/p' > file` |
| `awk` | 列统计：恶意 IP、慢接口 Top | `awk '{print $1}' \| sort \| uniq -c \| sort -nr \| head` |

建议把这几条命令记熟，生产排障时按场景取用即可。
